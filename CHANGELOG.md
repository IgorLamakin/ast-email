# История версий

Формат: `## vX.Y.Z — дата` и краткое описание того, что изменилось. Самая новая
версия — всегда сверху.

## v2.5.0 — 2026-08-26

### Безопасность (критично)

- **Устранена уязвимость SSTI → RCE.** Раньше контент письма прогонялся через
  Jinja2 с выключенным экранированием: введённый в текстовый блок шаблонный код
  (`{{ ... }}` / `{% ... %}`) исполнялся на сервере. Теперь рендер шаблонов — это
  строго безопасная подстановка по белому списку плейсхолдеров
  (`{{ greeting }}`, `{{ full_name }}`, `{{ position }}`, `{{ company }}`,
  `{{ phone }}`, `{{ sender_email }}`, `{{ address }}`, `{{ website }}`,
  `{{ recipient_email }}`), каждое значение HTML-экранируется, а всё остальное
  остаётся обычным текстом. (`backend/main.py`)
- **Electron-окна переведены на безопасный режим:** `nodeIntegration: false`,
  `contextIsolation: true` во всех окнах (wizard, main, update). Рендерер больше
  не имеет доступа к Node.js — только к ограниченному мосту `window.astAPI`
  (`preload.js`) с белым списком IPC-каналов. Предпросмотр письма рендерится в
  `sandbox`-iframe, у которого нет доступа к origin приложения. Это закрывает
  XSS→RCE через неэкранированные данные профиля/письма.
- **Исправлен path traversal в `/uploads`.** Раньше `filename` подставлялся в
  путь без проверки и файлы раздавались без авторизации — через `../` можно было
  прочитать `secret.key`/`app.db`. Теперь имя строго валидируется, путь обязан
  лежать внутри папки загрузок, добавлено ограничение расширений и лимит 20 МБ
  при загрузке (с поэтапным чтением, без удержания файла в памяти).
- **Backend больше не слушает сеть**: при прямом запуске `python main.py` —
  только `127.0.0.1`, как и при запуске из Electron.
- **«Сайт» в подписи больше не дублирует** `https://https://...`: адрес
  нормализуется на бэкенде.

### Надёжность / функциональность

- **Стандартные шаблоны больше не затираются при каждом запуске.** Содержимое
  5 стандартных писем синхронизируется только при смене версии «прошивки»
  (`TEMPLATE_SEED_VERSION`) — после обновления приложения. Если администратор
  отредактировал стандартное письмо, оно больше не откатывается к дефолту при
  следующем старте.
- **Во всех 5 стандартных шаблонах убраны Jinja-условия** (`{% if %}`) —
  заменены на всегда присутствующие поля с экранированием; ссылка на сайт стала
  `href="{{ website }}"` (сам адрес нормализуется на бэкенде, см. выше).
- **Логи отправок больше не раздувают базу**: в `EmailLog` сохраняется снимок
  письма с удалёнными base64/data-URI и лимитом длины (раньше — полный HTML с
  встроенными картинками).
- **Добавлен `DELETE /files/{id}`** — удаление загруженного файла (только
  своего) с очисткой диска.
- **Отправитель письма (From) теперь берётся из настроек SMTP** (`smtp_from`),
  а не из произвольного поля формы — почтовые серверы (Яндекс/Mail.ru/Gmail) не
  отказывают в письмах с несовпадающим ящиком. Значение `sender_email` остаётся
  для подписи (`{{ sender_email }}`).

### Сборка / версии

## v2.4.0 — 2026-08-20

- **Обновлены все 5 стандартных шаблонов писем** — единый дизайн в фирменных
  цветах (светло-серый + зелёный), структура под получение заявок, привлечение
  клиентов и имидж компании:
  - «Комплексная автоматизация производства» — общий обзор услуг и цифр;
  - «Поставка КИПиА и АСУТП» — категории оборудования, «КП за 24 часа»;
  - «Шкафы управления под ключ» — ШУ/ШР/ЩА, «бесплатно 3D-проект и спецификация»;
  - «Инжиниринг и разработка ПО» — SCADA/HMI, платформы, этапы «под ключ»;
  - «Реализованные проекты» — кейсы «Задача → Решение → Результат».
- В каждом письме: блок **«Наши бренды»**, блок **«Дополнительные бренды под
  заказ»**, единая CTA-кнопка с предзаполненной темой письма, подпись по
  визитке. Все `{{ плейсхолдеры }}` и Jinja2-условия сохранены.
- Бэкенд при старте теперь **обновляет** содержимое стандартных шаблонов у
  уже зарегистрированных пользователей (не только добавляет отсутствующие) —
  доработка `auto_seed_templates()` в `backend/main.py`.
- `updates/PLAN-EMAIL-TEMPLATES.md` — план и исследование для шаблонов.

## v2.2.1 — 2026-07-27

- Исправлен баг: загруженные картинки (в блоке «Изображение» и в фоне письма)
  не отображались вообще. Бэкенд отдавал относительный путь
  (`/uploads/имя.png`) вместо полного адреса — в собранном Electron-приложении
  такой путь никуда не ведёт.
- Более глубокая проблема того же корня, которая не была бы заметна на первый
  взгляд: даже с полным адресом (`http://localhost:8000/...`) картинка была бы
  битой у **любого получателя письма**, кроме самого отправителя — этот адрес
  существует только на компьютере отправителя и недоступен снаружи. Теперь при
  реальной отправке письма все локально загруженные картинки (обычные и
  фоновые) встраиваются прямо в HTML письма как `data:`-URI — получатель видит
  картинку без обращения к чьему-либо серверу.
- Уже сохранённые ранее шаблоны с битой относительной ссылкой на картинку
  чинятся автоматически при открытии в редакторе — не нужно перезагружать
  картинки заново.

## v2.2.0 — 2026-07-26

Этап 1 приведения в порядок раздела «Шаблоны» и блочного редактора:

- Исправлен баг: открытие на редактирование одного из 5 стандартных шаблонов
  показывало пустой холст, как у нового шаблона — теперь показывается понятное
  предупреждение вместо тихой пустоты, оригинал письма не теряется.
- Исправлен баг: клик по блоку-кнопке в редакторе уводил в браузер вместо
  выбора блока для настройки.
- Исправлен баг: предпросмотр письма в разделе «Отправка» не обновлялся при
  изменении email/обращения после выбора шаблона — теперь обновляется
  автоматически.
- **Вставка блока в любое место** — между существующими блоками появляется «+»
  для вставки именно там, а не только в конец.
- **Новый блок «Колонки»** — до 3 блоков в ряд, вёрстка на HTML-таблицах для
  корректного отображения в Outlook и других почтовых клиентах, где
  современный CSS (flex/grid) не поддерживается.
- **Настройки письма**: фон (цвет и/или картинка) для всего письма — раньше
  нигде не регулировался.
- **PDF-вложение**: у шаблона можно включить «Прикладывать PDF-версию письма
  при отправке» — получатель дополнительно получит файл-вложение с содержимым
  письма (без кнопок — в статичном документе они не нажимаются). Кнопка «Save
  to PDF» внутри самого письма технически невозможна — почтовые клиенты не
  выполняют JavaScript; поэтому реализовано как настройка шаблона, а не как
  блок.
- Больше настроек по каждому блоку: размер шрифта, отступ до следующего блока.

*Отложено на Этап 2 (после проверки этапа 1 в деле): изменение размера блока
мышкой за угол с сеткой выравнивания, плавные цветовые переходы между блоками
без чётких границ (ограничено поддержкой градиентов в Outlook), более глубокая
произвольная вложенность блоков.*

## v2.1.0 — 2026-07-25

- Новый дизайн: боковое меню вместо верхнего, единая цветовая палитра
  (промышленно-техническая тема — графит + сигнальный оранжевый), шрифты
  IBM Plex Sans/Mono.
- Новый раздел **«Настройки»** — SMTP теперь можно посмотреть и поменять прямо
  в приложении, не только один раз в мастере при установке. Пароль больше не
  передаётся и не хранится в открытом виде на фронтенде.
- Новый раздел **«Аккаунты»** (только для администратора) — все пользователи,
  сколько писем каждый отправил, какие у него шаблоны, и возможность сделать
  чужой шаблон общедоступным (или наоборот, снять с публикации).
- Номер версии теперь виден прямо в приложении (внизу бокового меню).
- Исправлен баг: после нажатия «Готово» в мастере настройки приложение иногда
  не открывалось само (закрывалось раньше, чем успевало показать основное
  окно) — теперь открывается надёжно.
- Исправлен баг: стандартные шаблоны не появлялись после регистрации первого
  пользователя на свежей базе данных.
- Исправлены `.bat`-скрипты — из-за скрытого символа в начале файла (BOM) они
  падали с ошибкой `"я╗┐@echo" is not recognized` при запуске.
- Автоматическая установка недостающих Python-зависимостей бэкенда при первом
  запуске приложения (раньше требовалось делать это вручную через консоль).
- Добавлена эта система версионирования: Git-история кода + архив всех
  собранных установщиков (`releases/`) + `release.bat` для выпуска обновлений.

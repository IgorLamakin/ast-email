# CHANGELOG исправлений (v32 → v33-fixed)

Все пункты соответствуют плану из файла `audit-i-plan-ispravleniy.md`. Отмечено, что
сделано, а что осознанно оставлено на будущее.

## Этап 1 — критические баги (сделано)

1. **Синхронизированы все маршруты фронтенд↔бэкенд.** Фронтенд больше не обращается к
   несуществующим `/templates/common`, `/templates/my`, `/email/preview`,
   `PUT /auth/me`. Используются реальные маршруты бэкенда (`GET /templates` с
   разделением «мои/общие» на клиенте, `POST /templates/{id}/preview`,
   `POST /templates/{id}/publish`, `PUT /users/{id}`).
2. **Добавлен `frontend/src/api.js`** — единая точка входа для всех запросов к
   бэкенду (`apiFetch`). Убраны все относительные `/api/...` пути, ломавшиеся в
   собранном Electron-приложении, и весь разнобой хардкод-адресов. Заодно: любой
   `401` от бэкенда теперь глобально разлогинивает пользователя вместо тихих ошибок.
3. **`POST /email/send`** больше не возвращает «успех», если SMTP не настроен —
   теперь явно возвращается ошибка 400 с понятным текстом, и в лог сохраняется
   реальный статус (`sent` / `not_sent`).
4. **Исправлена проверка успеха отправки** во фронтенде — она больше не сравнивает
   текст ответа бэкенда (который раньше был на английском и никогда не совпадал), а
   опирается на HTTP-статус через `apiFetch`.
5. **`HashRouter` вместо `BrowserRouter`** в `main.jsx` — чтобы обновление страницы в
   собранном приложении (`file://`) не приводило к белому экрану.
6. **Исправлено дублирование стандартных шаблонов** при перезапуске бэкенда —
   `auto_seed_templates`/`seed_templates.py` теперь реально проверяют каждый
   заголовок по отдельности, а не только общее количество.
7. **Удаление шаблона больше не ломает Аналитику.** В `EmailLog` добавлен снимок
   названия шаблона (`template_title`) на момент отправки; `template_id` стал
   nullable; при удалении шаблона связанные логи корректно отвязываются вместо
   образования «висячей» ссылки. Добавлена лёгкая авто-миграция схемы SQLite
   (`ALTER TABLE`) для уже существующих баз данных.

## Этап 2 — безопасность (сделано)

8. **Убран захардкоженный `SECRET_KEY`.** Теперь ключ либо берётся из переменной
   окружения `SECRET_KEY`, либо генерируется один раз и сохраняется в
   `%APPDATA%\ast-email-templates\secret.key` — он больше не лежит открытым текстом
   в поставляемых исходниках.
9. **Регистрация больше не выдаёт права администратора всем подряд.** Роль `ADMIN`
   автоматически получает только самый первый зарегистрированный пользователь в
   системе (обычно — тот, кто проходит мастер первого запуска). Все последующие
   регистрации получают обычную роль `USER`.
10. **Срок жизни токена синхронизирован** — реально используется 12 часов (раньше
    константа `ACCESS_TOKEN_EXPIRE_MINUTES=30` была объявлена, но не использовалась,
    и токен реально жил 15 минут). Добавлена реакция фронтенда на протухший токен
    (см. п.2).
11. **Закреплена версия `bcrypt==3.2.2`** в `requirements.txt` — известный конфликт
    `passlib==1.7.4` с `bcrypt>=4.0`.

Дополнительно (не было в исходном плане явным пунктом, но нужно для согласованности
с п.9): в `PUT /users/{id}` добавлена возможность администратора менять роль
пользователя (только не себе самому), с схемой `UserUpdate.role` — раньше в API
вообще не было способа выдать/забрать права администратора после регистрации.

## Этап 3 — качество и порядок (сделано)

12. `preload.js` подключён в `webPreferences` обоих окон Electron (раньше файл
    существовал, но нигде не был указан).
13. Удалены мёртвый `TemplateEditor.jsx` и неиспользуемый `electron/start-backend.bat`
    (ссылка на него убрана и из `electron/package.json → files`).
14. Удалён устаревший `README-v30.txt`.
15. `__pycache__` вычищен из проекта.
16. Добавлено экранирование пользовательского текста (`escapeHtml`) в
    `renderBlocksToHtml()` внутри `BlockEditor.jsx` — теги, введённые в текстовые
    поля блоков, больше не могут исказить итоговый HTML письма. Jinja-плейсхолдеры
    (`{{ full_name }}` и т.п.) по-прежнему вставляются как есть, так как их и должен
    подставлять бэкенд при отправке.

## Этап 4 — проверка

- Все изменённые `.py`-файлы прошли `python -m py_compile` без ошибок.
- `electron/main.js` и `frontend/src/api.js` прошли `node --check` без ошибок.
- Полный прогон в реальном Windows-окружении (мастер → SMTP → отправка → аналитика →

## Осознанно не сделано (см. «мелкие замечания» в отчёте) — не блокирует работу

- Полный переход `contextIsolation: true` + `contextBridge` для Electron не сделан —
  это отдельный, более трудоёмкий рефакторинг (нужно пройтись по всем местам, где
  страница может использовать Node API). Текущая конфигурация
  (`nodeIntegration: true`, `contextIsolation: false`) оставлена как есть, так как
  риск ограничен: окна грузят только собственный локальный код приложения.
- 404 на `/vite.svg` в `index.html` — косметическая мелочь, не влияет на работу.
- Список провайдеров SMTP в мастере настройки не расширялся (не было явного бага,
  просто ограниченный список).

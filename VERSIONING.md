# Версии, обновления и откат — как это работает

Коротко: теперь у проекта есть **история** (как в Google Docs — можно посмотреть,
что было раньше, и вернуться к любой версии) и **обновление одной кнопкой**
вместо полного сноса и переустановки. Ниже — как это устроено и что конкретно
нужно делать.

---

## Как это устроено (для понимания, не обязательно к прочтению)

- **Git** — программа для хранения истории кода. Каждый раз, когда выходит новая
  версия, она сохраняется как "снимок" (commit) с меткой версии (tag). Можно
  посмотреть весь список снимков и вернуться к любому из них.
- **`releases\`** — папка внутри проекта, где копится **каждый собранный
  установщик** (`.exe`) под своим номером версии. Это и есть "все версии
  приложения", которые можно установить в любой момент.
- **`release.bat`** — один скрипт, который делает всё сразу: сохраняет снимок в
  Git, собирает установщик, кладёт его в `releases\`.
- **`CHANGELOG.md`** — простой текстовый файл с человеко-читаемым описанием,
  что изменилось в каждой версии (я буду заполнять его сам перед тем, как
  прислать вам обновление).

## Единоразовая настройка (сделать один раз, сейчас)

### Установите Git для Windows

1. Скачайте с официального сайта: https://git-scm.com/download/win
2. Запустите установщик, везде оставляйте настройки по умолчанию (просто
   нажимайте «Next» / «Далее»), в конце — «Install» / «Установить».
3. Откройте **новое** окно PowerShell и проверьте:
   ```
   git --version
   ```
   Должно вывести что-то вроде `git version 2.45.0.windows.1`.

### Первый запуск release.bat создаст историю автоматически

Ничего дополнительно делать не нужно — при самом первом запуске `release.bat`
сам инициализирует Git в папке проекта и сохранит текущее состояние как
стартовую точку. Дальше просто следуйте обычному потоку ниже.

---

## Обычный порядок работы (для каждого следующего изменения)

Это то, что будет происходить дальше, снова и снова:

1. **Вы пишете мне**, что нужно поправить или добавить.
2. **Я вношу изменения** в код, сам поднимаю номер версии и дописываю
   `CHANGELOG.md` с описанием того, что изменилось.
3. **Я присылаю вам файлы** (либо отдельные изменённые файлы, либо весь архив
   проекта целиком — как раньше).
4. **Вы заменяете файлы** в папке `C:\ast-project\email-templates-project-v32-fixed\`.
5. **Вы запускаете ОДИН скрипт:**
   ```
   cd C:\ast-project\email-templates-project-v32-fixed
   .\release.bat
   ```
   Он сам: сохранит снимок в Git → соберёт установщик → положит его в
   `releases\` → покажет путь к готовому файлу.
6. **Вы запускаете получившийся `.exe` из папки `releases\`** — он поставится
   **поверх** текущей версии, ничего сносить не нужно. Ваши данные (аккаунт,
   шаблоны, контакты, настройки SMTP) никуда не денутся — они хранятся отдельно
   от программы, в `%APPDATA%`, и установщик их не трогает.

Вот и всё — шаги 4-6 и есть то самое «просто обновляем», без сноса.

## Как посмотреть все версии

**Список версий кода (Git):**
```
cd C:\ast-project\email-templates-project-v32-fixed
git log --oneline
```
Покажет что-то вроде:
```
a1b2c3d (HEAD, tag: v2.1.0) v2.1.0: Редизайн, Настройки, Аккаунты
9f8e7d6 (tag: v2.0.0) Начальная версия
```

**Человеко-читаемое описание каждой версии:**
Откройте файл `CHANGELOG.md` в корне проекта — там всё расписано текстом.

**Все собранные установщики:**
Откройте папку `releases\` — там лежит `.exe`-файл для каждой версии, которую
мы когда-либо выпускали.

## Как откатиться назад

Тут два разных смысла «откатиться» — на всякий случай оба:

### Откатить САМО ПРИЛОЖЕНИЕ (то, что реально установлено и чем вы пользуетесь)

Просто откройте папку `releases\`, найдите нужную старую версию
(например, `AST-Email-Templates-Setup-2.0.0.exe`) и запустите её. Она
установится поверх текущей, никаких данных не потеряется.

*Небольшая оговорка: это должно работать «из коробки» по тому, как устроены
установщики Windows (NSIS) — но у меня нет возможности проверить это лично на
реальной Windows-машине. Рекомендую один раз попробовать откат на
низко-рискованном примере (например, поставить текущую версию поверх самой
себя), чтобы убедиться, что всё проходит гладко, прежде чем полагаться на это
в важный момент.*

### Откатить КОД (если вдруг понадобится вернуться к старой версии перед новой сборкой)

```
cd C:\ast-project\email-templates-project-v32-fixed
git checkout v2.0.0
```
Это вернёт файлы проекта к состоянию версии 2.0.0. Дальше можно собрать её
заново через `.\build-electron.bat`, если понадобится. Чтобы вернуться обратно
к самой последней версии:
```
git checkout main
```
(или `git checkout master` — зависит от того, как называется основная ветка;
`git branch` покажет, какая сейчас активна)

## Частые вопросы

**Нужно ли мне самому вводить номер версии?**
Нет. Я сам поднимаю номер версии в коде и заполняю `CHANGELOG.md` перед тем,
как прислать вам файлы. Вам достаточно один раз запустить `release.bat` — он
сам разберётся, какая сейчас версия.

**А если я запущу `release.bat` дважды подряд без новых файлов от вас?**
Ничего страшного не произойдёт — Git просто скажет, что сохранять нечего
(нет изменений), а сборка пересоберёт то же самое ещё раз. Единственное — тег
версии уже будет существовать, скрипт покажет предупреждение и просто
пропустит создание тега, это нормально.

**Что если `release.bat` или `git` выдаёт непонятную ошибку?**
Скопируйте текст ошибки целиком и пришлите мне — разберём.

**Нужно ли удалять папку `releases\` время от времени?**
Файлы установщиков довольно увесистые (обычно 60-150 МБ каждый). Если версий
накопится много и место на диске станет важно — можно смело удалить самые
старые установщики из `releases\`, которые точно не понадобятся. На саму
работу приложения и на Git-историю кода это не влияет никак — это просто
папка со сложенными файлами, не служебные данные Git.
